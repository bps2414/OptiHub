- `GameLibraryEntry`
- `GameLibrarySnapshot`

Implement these exact async Tauri command signatures:

```rust
#[tauri::command]
pub async fn get_game_library() -> Result<GameLibrarySnapshot, AppError>

#[tauri::command]
pub async fn refresh_game_library() -> Result<GameLibrarySnapshot, AppError>
```

Implement Steam root lookup using `winreg` with this exact registry preference order:
1. `HKEY_CURRENT_USER\Software\Valve\Steam` value `SteamPath`
2. `HKEY_LOCAL_MACHINE\SOFTWARE\WOW6432Node\Valve\Steam` value `InstallPath`

Parse `libraryfolders.vdf` from `<steam_root>/steamapps/libraryfolders.vdf` using `keyvalues_serde::from_str`. Normalize every discovered library into a canonical `PathBuf` and scan manifests under `<library>/steamapps/appmanifest_*.acf`.

Parse each manifest into a typed struct that extracts these exact fields when present:
- `appid`
- `name`
- `installdir`

Normalize each Steam detection into one `GameLibraryEntry` with:
- `id = format!("steam:{appid}")`
- `display_name = manifest name when non-empty`
- `executable_path = ""` for now when the actual `.exe` cannot be derived safely from the manifest alone
- `install_dir = <library>/steamapps/common/<installdir>`
- `source = GameSource::Steam`
- `steam_app_id = Some(appid)`
- `last_seen_at = Some(current timestamp string)`

Keep the command best-effort:
- missing registry keys should return an empty `entries` list, not a hard failure
- malformed `libraryfolders.vdf` or one broken manifest must skip that file and continue
- `refresh_game_library()` should perform a fresh scan every time
- `get_game_library()` may call the same scan path for now, but must remain available as a separate wrapper so Phase 3 plan 02 can evolve it into a persisted read path

Run disk-heavy scan work inside `tauri::async_runtime::spawn_blocking` so the desktop shell does not block during library refresh.
