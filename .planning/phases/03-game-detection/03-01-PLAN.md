```rust

```

Use `tauri::AppHandle` even though this plan is detection-only so the command surface does not need to change in 03-02 when app-data-backed manual reconciliation is added.

Implement Steam root lookup using `winreg` with this exact registry preference order:
1. `HKEY_CURRENT_USER\Software\Valve\Steam` value `SteamPath`
2. `HKEY_LOCAL_MACHINE\SOFTWARE\WOW6432Node\Valve\Steam` value `InstallPath`

Parse `libraryfolders.vdf` from `<steam_root>/steamapps/libraryfolders.vdf` using `keyvalues_serde::from_str`. Normalize every discovered library into a canonical install-root key with a helper like:

```rust
fn normalize_install_root(path: &Path) -> String
```

This helper must:
- canonicalize when possible
- lowercase on Windows
- normalize path separators
- trim trailing separators

Scan manifests under `<library>/steamapps/appmanifest_*.acf` and parse these exact fields when present:
- `appid`
- `name`
- `installdir`

Normalize each Steam detection into one `GameLibraryEntry` with:
- `id = format!("steam:{appid}")`
- `display_name = manifest name when non-empty`
- `executable_path = None`
- `install_dir = <library>/steamapps/common/<installdir>`
- `source = GameSource::Steam`
- `steam_app_id = Some(appid)`
- `removable = false`
- `user_added = false`
- `last_seen_at = Some(current timestamp string)`

Keep the command best-effort:
- missing registry keys return an empty `entries` list, not a hard failure
- malformed `libraryfolders.vdf` or one broken manifest skips that file and continues
- `refresh_game_library(app)` performs a fresh scan every time
- `get_game_library(app)` may call the same scan path for now, but must keep the same `AppHandle` signature so 03-02 can layer app-data-backed reconciliation without command churn

Run disk-heavy scan work inside `tauri::async_runtime::spawn_blocking`.

Do not add any cover-art, SteamDB, metadata cache, or detail-page logic here. This plan only delivers detection and management data for Phase 3.
